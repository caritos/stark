# Stark for Apple Watch Implementation Plan (revised for approach B)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A watchOS app for Stark: an Up Next list and complications read from the watch's own EventKit store, and tap-to-complete and add-by-dictation that the watch sends to the iPhone app, which does the writing.

**Architecture:** EventKit writes are prohibited on watchOS (Task 0 finding), so the watch reads and the iPhone writes. A command link in `StarkKit` (`WatchEnvelope`/`WatchReply`, `WatchCommandHandler` on the phone, `WatchOutbox` on the watch, a `WatchTransport` protocol) carries `complete` and `add` commands over WatchConnectivity; only thin glue touches `WCSession`. Reads reuse `WidgetAgenda`, `EventKitProvider.swift` (by file reference) and the widget's Lock Screen text helpers; dictation reuses `QuickAddParser`.

**Tech Stack:** Swift 5.9 package + SwiftUI + WidgetKit + EventKit + WatchConnectivity, Swift Testing, hand-edited `ios/App/Stark/Stark.xcodeproj`.

**Spec:** `docs/superpowers/specs/2026-11-24-watch-app-design.md` (revised 2026-11-24 after the spike; the owner chose B). Spike findings: `docs/superpowers/specs/2026-11-24-watch-spike-findings.md`; the throwaway spike target is on branch `watch-spike` (c701d31) and is a useful reference for the watch target and widget extension pbxproj entries.

## Global Constraints

- Native only; watchOS 10 floor; `StarkKit` platforms `[.iOS(.v17), .macOS(.v14), .watchOS(.v10)]`; `swift test` must still run on the Mac.
- Apple Calendar and Reminders are the only store. All writes happen in the iPhone app; the watch never writes and never touches `sidecar.json`. `AppleItemRepository.swift` must NOT be compiled into any watch target (it does not compile there).
- Bundle ids: watch app `com.caritos.todo-txt.watchkitapp`, team `3U8L77G9QV`, automatic signing. Watch version and build track the iOS app's; `ship.sh` bumps both.
- Tests first for logic (Swift Testing: `import Testing`, `@Test`, `#expect`), seen red before green. Views, glue and styling are verified by build and by screenshot/device, not unit tests.
- No logic in views. Nothing new stored or sent beyond the system's watch-to-phone link; dictation uses the system's speech recognition and the copy must say Apple may process it (never "nothing is sent").
- Queue rules: at most 20 waiting envelopes (refuse the 21st visibly), an envelope waiting over 7 days shows "Not delivered"; the phone keeps at most 200 applied envelope ids; nothing is dropped silently.
- No watchOS simulator runtime is installed and the Mac has about 13 GB free: do not download a runtime without asking the owner. Never install on a real device without telling the owner.
- Never submit for App Store review; TestFlight only. Never retype bulk IDs.
- Worktree `.claude/worktrees/watch-app` (branch `watch-app`); full suite on the merged result before finishing.

## Review Focus

- A command delivered twice (redelivered `transferUserInfo`): applied once, same reply (Task 3).
- The phone unreachable: the command is queued and shown as waiting, then done when the reply arrives (Task 3).
- A failed phone write: the completed row returns with the error; an add shows the failure and keeps the draft (Tasks 5, 6).
- Empty or whitespace dictation: no draft, nothing sent (Task 2).
- Access denied, not asked or write-only on the watch, and a watch store with no sources: a readable state, never a blank list (Task 4).

### Task 3: The command link (Kit) and the iPhone receiver

**Files:** Create the three `Watch/` Kit files named in File Structure (`WatchLink.swift`, `WatchCommandHandler.swift`, `WatchOutbox.swift`), `ios/Tests/StarkKitTests/WatchLinkTests.swift`, `WatchCommandHandlerTests.swift`, `WatchOutboxTests.swift`, and `ios/App/Stark/Stark/WatchLinkReceiver.swift`; Modify the iOS app's launch code (`StarkApp.swift`) and `project.pbxproj` (new file).

**Interfaces:**
- Consumes: `ItemRepository` (`addEvent(_:calendarID:)`, `addReminder(_:listID:)`, `complete(_:on:)`), `FakeItemRepository`, `DestinationLabel.addedNotice(calendar:)`, `DestinationLabel.warning(for:)`, `AppleCalendarInfo` (`isLocalOnly`), `WatchAddDraft`.
- Produces:
  ```swift
  public enum WatchCommand: Codable, Equatable, Sendable {
      case complete(identifier: String, externalID: String?, occurrence: Date)  // reminders only
      case add(WatchAddDraft)
  }
  public struct WatchEnvelope: Codable, Equatable, Sendable { public let id: UUID; public let sentAt: Date; public let command: WatchCommand }
  public enum WatchReply: Codable, Equatable, Sendable { case done(notice: String?, warning: String?); case failed(String) }
  public struct WatchReplyEnvelope: Codable, Equatable, Sendable { public let id: UUID; public let reply: WatchReply }
  public protocol WatchTransport: Sendable {
      var isReachable: Bool { get }
      func send(_ envelope: WatchEnvelope) async throws -> WatchReply   // live message; throws when it cannot be delivered
      func queue(_ envelope: WatchEnvelope)                             // transferUserInfo
      func reply(_ reply: WatchReplyEnvelope)                           // phone to watch (live if reachable, else queued)
  }
  public protocol AppliedIDStore: Sendable { func contains(_ id: UUID) -> Bool; func insert(_ id: UUID) }
  public struct UserDefaultsAppliedIDStore: AppliedIDStore { public init(defaults: UserDefaults = .standard, key: String = "watch.appliedIDs.v1", limit: Int = 200) }
  public actor WatchCommandHandler {
      public init(repository: ItemRepository,
                  destinations: @escaping @Sendable () async -> (calendar: AppleCalendarInfo?, list: AppleCalendarInfo?),
                  applied: AppliedIDStore)
      public func handle(_ envelope: WatchEnvelope) async -> WatchReply
  }
  public protocol WatchPendingStore: Sendable { func load() -> [WatchEnvelope: Date]; func save(_ pending: [WatchEnvelope: Date]) }  // waiting ones, so they survive a relaunch (WatchEnvelope is Hashable via id)
  @MainActor @Observable public final class WatchOutbox {
      public enum Status: Equatable { case sending, waiting, done(WatchReply), failed(String) }
      public private(set) var statuses: [UUID: Status]
      public private(set) var lastError: String?
      public init(transport: WatchTransport, pending: WatchPendingStore,
                  now: @escaping @Sendable () -> Date = Date.init, maxWaiting: Int = 20, maxAge: TimeInterval = 7 * 24 * 3600)
      @discardableResult public func submit(_ command: WatchCommand) async -> UUID?   // nil and lastError set when 20 are already waiting
      public func receive(_ reply: WatchReplyEnvelope)
      public func expireOld()                                                         // waiting past maxAge -> .failed("Not delivered")
  }
  ```
  (Make `WatchEnvelope` `Hashable`.)
