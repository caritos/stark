# Weather in the agenda Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** An opt-in forecast glyph and high/low in the agenda day headers, from MET Norway, using an approximate location.

**Architecture:** Pure Kit parser/formatter/state; thin app wiring (`WeatherModel`, `LocationProvider`, Settings section, header view).

**Tech Stack:** Swift 6 / SwiftUI, CoreLocation, URLSession, Swift Testing, Go + static HTML.

**Spec:** `docs/superpowers/specs/2026-11-18-weather-design.md`

## Global Constraints
- Worktree; tests first (red, then green); small commits; never `git add` `ios/.build` or `.superpowers`.
- Kit tests: `cd ios && swift test --scratch-path /private/tmp/claude-501/wx` (new suites also under `TZ=Pacific/Honolulu`, `America/New_York`, `Asia/Tokyo`). Web: `cd web && make test-fast`, `make e2e` (Node 24: `nvm use` inside `web/`, same shell).
- OFF by default; no network call and no location prompt unless the toggle is on. Send only the position rounded to 0.1 degree, over https, with User-Agent `Stark-iOS https://stark.caritos.com`. Never store or log coordinates. Attribution line "Forecast data from MET Norway" in the Settings footer.
- Day math through a Gregorian calendar with the phone's time zone (as the planner does). Tests use fixture JSON in the test file (a small `compact` response), no network.
- New Swift files in `ios/App/Stark/Stark/` need no pbxproj edit, except `PrivacyInfo.xcprivacy` and `Info.plist` edits.
- Copy: privacy page keeps "LAST UPDATED: NOVEMBER 2026"; every page keeps the `Build @@BUILD_ID@@` footer once; the privacy page and FAQ must stop claiming that Stark sends nothing anywhere (reword with web tests first).

## Review Focus
- Toggle off: zero requests, zero location use. Toggle on with location denied: no crash, no banner, Settings footer says why.
- Forecast days grouped by LOCAL day (a UTC evening hour belongs to the next local day in Tokyo; Honolulu the previous), partial first day, DST day.
- Fewer than 4 hours for a day (the last day): skip the day rather than show a misleading high/low.
- Fahrenheit for a US locale, Celsius otherwise; negative temperatures and rounding (-0.4 shows "0°" not "-0°").
- Bad JSON, an empty timeseries, HTTP error, offline: no crash, no stale wrong day shown.
- Location moves more than 0.1 degree or an hour passes: refetch; otherwise reuse the cache.
