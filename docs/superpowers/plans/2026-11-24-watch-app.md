# Stark for Apple Watch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A standalone watchOS app for Stark: Up Next list and complications, tap-to-complete reminders, and add-by-dictation, all on the watch's own EventKit store.

**Architecture:** A new watchOS app target (plus a watch widget extension) embedded in the iOS app. All logic goes in `StarkKit` (`WatchAgendaModel`, `WatchAddDraft`, `WatchAddModel`), reusing `WidgetAgenda`, `QuickAddParser`, `DestinationLabel` and `ItemRepository`. `EventKitProvider.swift` and `AppleItemRepository.swift` (app target today, no UIKit) are compiled into the watch targets by file reference, as the iOS widget already does with `EventKitProvider.swift`. Views are thin.

**Tech Stack:** Swift 5.9 package + SwiftUI + WidgetKit + EventKit, Swift Testing, hand-edited `ios/App/Stark/Stark.xcodeproj` (folder-synced, no XcodeGen here).

**Spec:** `docs/superpowers/specs/2026-11-24-watch-app-design.md` (approved 2026-11-24).

## Global Constraints

- Native only; watchOS 10 floor, `StarkKit` platforms become `[.iOS(.v17), .macOS(.v14), .watchOS(.v10)]`; `swift test` must still run on the Mac.
- Apple Calendar and Reminders are the only store; the watch never touches `sidecar.json`.
- Bundle ids: watch app `com.caritos.todo-txt.watchkitapp` (my call in the spec), team `3U8L77G9QV`, automatic signing. Watch version and build track the iOS app's; `ship.sh` bumps both.
- Tests first for logic (Swift Testing, `import Testing`, `@Test`, `#expect`), seen red before green. Views and styling are verified by screenshot/device, not unit tests.
- No logic in views. Nothing new stored or sent by Stark; dictation uses the system's speech recognition and the copy must say Apple may process it (not "nothing is sent").
- Never submit for App Store review; TestFlight only. Never retype bulk IDs.
- Run the work in a worktree (`EnterWorktree`); full suite on the merged result before finishing.

## Review Focus

- Empty or whitespace dictation: no draft, nothing saved (test in Task 2).
- Double tap on a reminder (or a repeating one): exactly one completion, row not duplicated (Task 4).
- Access denied, not asked or write-only on the watch: a readable state, never a blank list (Task 3).
- A completion that fails in the store: the row returns and an error shows (Task 4).
- The watch's default calendar is local-only (does not sync): the confirm screen says so, still saves (Task 5).

### Task 5: Add by dictation

**Files:**
- Create: `ios/Sources/StarkKit/Watch/WatchAddModel.swift`, `ios/Tests/StarkKitTests/WatchAddModelTests.swift`, add and confirm views in `StarkWatch/`

**Interfaces:**

- Produces:
  ```swift
  @MainActor @Observable public final class WatchAddModel {
      public enum Phase: Equatable { case idle, confirming(WatchAddDraft), saving, saved(String), failed(String) }
      public private(set) var phase: Phase
      public init(repository: ItemRepository,
                  destinations: @escaping @Sendable () -> (calendar: AppleCalendarInfo?, list: AppleCalendarInfo?),
                  now: @escaping @Sendable () -> Date = Date.init)
      public func dictated(_ text: String)     // idle -> confirming, or stays idle when no draft
      public var warning: String?              // local-only destination warning while confirming
      public func confirm() async              // saves; phase .saved("Added to X · account")
      public func cancel()                     // back to idle, saves nothing
  }
  ```
